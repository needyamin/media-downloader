Project Overview

The repository is centered around a Tkinter-based desktop application launched through run.py. The root launcher adds src/ to the import path and runs the main GUI script at src/desktop_tools/app/media_download.py.

The primary app handles media downloads using yt-dlp, offers quality and format controls, monitors the clipboard for media links, supports playlist downloads, integrates a system tray menu, and ships extra tools through the menu bar.

The codebase is organized so future desktop tools can be added cleanly without turning the repository root into a large collection of unrelated scripts.

Feature Set

The core application is more than a downloader; it is a small desktop tools platform.

Media Downloads

Download videos and audio from supported public sources using yt-dlp, including support for playlists and output format selection.

Clipboard Monitoring

Tracks newly copied media URLs, auto-pastes the latest one, and keeps memory usage lightweight with a bounded recent history.

Quality and Format Controls

Provides menu-based controls for video quality, audio bitrate, and output format including mp4, webm, and mkv.

System Tray Workflow

Supports running in the background from the tray and mirrors major menu-bar actions through the tray menu for quick access.

Background FFmpeg Management

Automatically finds, downloads, configures, verifies, and updates FFmpeg in the background, with visible in-app logging.

Cross-Tool Extensibility

Separates shared helpers from tool-specific app code so new GUI modules can be added in the future with less coupling.

Included Desktop Tools

Main Window

Media Downloader

The primary application for entering URLs, selecting download preferences, monitoring progress, and viewing logs.

  • Runs from src/desktop_tools/app/media_download.py
  • Launches through run.py
  • Owns the main menu, tray, status bar, and download workflow
Integrated Tool

Video Converter

Opened from the menu bar and uses the shared managed FFmpeg runtime rather than bundling its own separate installation.

  • Exposed through Tools -> Video Converter
  • Implemented in converter_app.py
  • Uses background FFmpeg preparation for a non-blocking UI
Integrated Tool

BG Remover

A second GUI tool integrated into the same desktop experience, opened directly from the downloader menu bar.

  • Exposed through Tools -> BG Remover
  • Implemented in background_remover_app.py
  • Uses the same shared project structure and asset pipeline

FFmpeg Lifecycle and Logging

1

Automatic startup check

When the GUI opens, the app starts an FFmpeg background sync automatically instead of blocking the interface.

2

Search existing installs

The shared module checks the managed install directory and expected local system paths before downloading anything.

3

Download if missing

If no working FFmpeg binary is found, the app downloads an FFmpeg package automatically, extracts it, copies the executables into the managed directory, and verifies them.

4

Track release metadata

The shared module records install details and release tags so later update checks can determine whether a newer FFmpeg version is available.

5

Visible logging

FFmpeg logs are intentionally shown in the normal in-app log, even when global debug logging is disabled, so users can see what is happening.

FFmpeg Sources and Controls

  • Shared module: src/desktop_tools/shared/ffmpeg.py
  • Managed install location: %LOCALAPPDATA%\Media Downloader\ffmpeg
  • Metadata file: ffmpeg_metadata.json
  • Manual menu action: Settings -> Install / Update FFmpeg

User Flow

Step 1

Launch the app through python run.py or a packaged executable.

Step 2

Paste a supported media URL manually or let the clipboard watcher populate the latest copied link.

Step 3

Choose video quality, audio bitrate, format, destination folder, and playlist behavior from the UI and menus.

Step 4

Use the same app window, the tray menu, or the integrated companion tools as needed while FFmpeg remains shared.

Runtime Flags

Flag Current Default / Example Purpose
debug_logging false Controls extra internal debug logging. FFmpeg activity remains visible even when this is off.
ui_queue_poll_ms 150 Sets the UI queue polling interval used for thread-safe GUI updates.
clipboard_poll_ms_active 1200 Polling interval for clipboard checks while the app is active.
clipboard_poll_ms_background 2500 Polling interval for clipboard checks while the app is backgrounded.
clipboard_recent_limit 10 Limits remembered clipboard URLs to keep the app lightweight.
progress_log_min_interval_ms 1500 Minimum interval for progress log updates.
progress_ui_min_interval_ms 250 Minimum interval for progress UI refreshes.
max_log_lines 400 Keeps the visible log bounded in memory.
disabled_domains ["youtubes.com", "facebooks.com"] Domain blocklist applied even if yt-dlp could otherwise support those sites.

Build, Packaging, and Release Flow

Windows Build Pipeline

The Windows release flow compiles the application with Nuitka and then builds an Inno Setup installer.

  • Main script: src/desktop_tools/app/nutika_build.py
  • Wrapper script: src/desktop_tools/app/build_installer.bat
  • Installer script: src/desktop_tools/app/installer/setup.iss
  • Output directory: release/windows

Windows command

python "src\desktop_tools\app\nutika_build.py"

Linux AppImage Pipeline

The Linux flow creates a PyInstaller onedir bundle and wraps it into an AppImage.

  • Main script: src/desktop_tools/app/linux_appimage_build.py
  • Shell wrapper: src/desktop_tools/app/build_linux_appimage.sh
  • Output directory: release/linux
  • Generated artifact: Media-Downloader-x86_64.AppImage

Linux commands

python3 "src/desktop_tools/app/linux_appimage_build.py"
./src/desktop_tools/app/build_linux_appimage.sh

Windows Signing and SmartScreen Strategy

To reduce SmartScreen and unknown-publisher warnings for this open-source project, the repository includes support for optional signing through SignPath Foundation.

  • Workflow file: .github/workflows/windows-signpath.yml
  • Artifact config: .signpath/artifact-configurations/windows-release.xml
  • Targets: Media-Downloader.exe and MediaDownloader_Setup.exe

If signing is configured, the release pipeline signs the Windows artifacts. If it is not configured yet, the build can still produce unsigned artifacts so the release process remains usable.

Design Notes

  • The root stays minimal so the project is easier to maintain and extend.
  • Shared modules centralize cross-tool logic such as FFmpeg handling, path detection, icon loading, and window centering.
  • Tool-specific code lives under src/desktop_tools/app/ so future GUI modules can be added without heavy refactors.
  • Release artifacts are separated under release/windows and release/linux.

Dependencies and Stack

GUI

Tkinter for the main application and windowing, with CustomTkinter used for the background remover experience.

Media Engine

System Integration

Packaging

Nuitka and Inno Setup for Windows, PyInstaller and AppImage tooling for Linux distribution.
